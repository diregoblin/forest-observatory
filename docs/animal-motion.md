# Общие анимации животных

В этой итерации использованы установленные **Blender 4.5.3 LTS** и штатный
**AnimationPlayer / AnimationLibrary** Redot. Старый Blender MCP на этом хосте
не был доступен; сервисы/пакеты не устанавливались. Отдельный Blender-процесс
работал в background/factory-startup на CPU, не трогая пользовательскую сцену.

- Редактируемый источник: `art/source/forest-animal-motion.blend`.
- Восемь Blender Actions: idle, walk, hop, feed, sleep, alert, fly, swim.
- Девять каналов позы: шаг, наклон головы, уши, дыхание, подъём тела, хвост,
  взмах крыльев, раскрытие и запястье.
- `data/animation/animal_motion.json` содержит выборку этих кривых.
- `data/animation/animal_motion.tres` — нативная AnimationLibrary с теми же кривыми.

Это небольшой общий набор поз, не биомеханически калиброванный rig и не motion capture.
Части ресурсной модели имеют роли и локальные опорные точки. Один общий
шейдер деформирует объединённый индексированный mesh, без отдельных draw call
на каждую лапу. AnimationPlayer управляет instance shader parameters.
Наблюдатель деформирует треугольники теми же кривыми и правовинтовыми
поворотами; проверка отдельно ловит перепутанное направление оси Z.

У дрозда есть плечо и запястье: ресурсные роли `flight_wing`, `flight_tip` и
`flight_leg` раскрывают маховые перья, складывают крыло вдоль тела и подбирают
лапки. CPU и GPU применяют запястье → плечо → наклон корпуса в одинаковом порядке.
Переходы между наземной и полётной позами занимают .18 отображаемой секунды;
позы для выбора объекта используют тот же результат. Семь неполётных клипов
сохранили исходные семь каналов, два новых у них нулевые.

Время берётся из завершённых модельных тиков и их интерполяции, а не `TIME`
или настенных часов. Пауза останавливает позы. Клип выбирается по настоящему
действию/признакам животного, но никогда не перемещает авторитетную позицию.
Для каждого показываемого участка сохранённого пути отдельно определяется,
движется ли животное. Короткий подход к еде получает locomotion-клип своего
ресурса, даже если конечное действие того же модельного тика уже «ест».
Неподвижный участок не продолжает прыжок/ходьбу по одному лишь конечному действию.
Выбор использует только отделённый presentation frame, без чтения worker-модели.
Плавание выводит тело к уровню воды; его скорость и стоимость считаются моделью.

## Воспроизведение

Из корня проекта:

```sh
python3 tools/gpu_guard.py -- /home/pavel/.local/opt/blender-4.5.3-linux-x64/blender --background --factory-startup --threads 2 --python tools/build_animal_motion.py
./tools/run.sh --headless --script res://tools/build_motion_library.gd
./tools/run.sh --headless --script res://tools/check_animal_motion.gd
./tools/run.sh --headless --script res://tools/check_short_animal_motion.gd
./tools/run.sh --headless --script res://tools/check_bird_flight.gd
```

Первая команда — воспроизводимая авторская заготовка. После ручного изменения
Blender Actions экспортёр нужно адаптировать для чтения отредактированных
F-curves: текущий генератор заново создаёт исходные Actions и их выборку.
Не выдавать наличие `.blend` за автоматический импорт произвольного rig.

`art/source/.gdignore` отключает неявный импорт `.blend` движком: для запуска
игры Blender не нужен. Тесты сравнивают AnimationLibrary и CPU-кривые в 97
моментах каждого клипа. Короткий Forward+ fixture дополнительно проверяет
параметры живого AnimationPlayer, изменение picking-геометрии и чистоту views.
