# GPU: отсечка 70 °C и разбор затрат без нового прогрева

Запрос Павла, 2026-11-01, после reboot: выяснить, что нагрузило GPU, и
автоматически останавливать эксперименты при 70 °C. Нагрузочный прогон не повторяли.

**Текущий итог после продолжения по просьбе Павла:** отсечка и три оптимизации
установлены. Вершины 13 365 900 → 2 413 733 при неизменных треугольниках и
популяции; пространственные батчи вместо общедолинных; дешёвое sky radiance.
Ниже сначала сохранён первоначальный аудит, затем результаты реализации.

## Отсечка установлена и проверена

`tools/run.sh` теперь запускает движок через `tools/gpu_guard.py`. Его используют
также `preview.sh`, `preview_isolated.sh` и engine-проверки из `check.sh`.
Это независимый Python-процесс, а не обработчик игрового кадра.

- Перед запуском проверяются UUID и температура **всех** NVIDIA GPU.
- При >=70 °C запуск запрещён; в работе первое такое значение останавливает
  группу процессов **только этого эксперимента**: TERM, затем KILL через 0,5 с.
- Период опроса 0,5 с. Ошибка/пустой ответ/NaN/исчезновение GPU/таймаут
  `nvidia-smi` (2 с) также останавливают эксперимент, а не мониторинг.
- Сигналы INT/TERM/HUP сторожу завершают его группу нагрузки. Linux
  `PR_SET_PDEATHSIG` убивает прямой процесс нагрузки при SIGKILL самого сторожа.
- Порог можно только снизить; штатного флага отключения нет. Код выхода:
  86 — температура, 87 — неисправная телеметрия/запуск, обычный код приложения
  сохраняется. Существующие saves не перезаписываются; аварийного autosave нет.
- Это программный опрос, не аппаратная гарантия отсутствия выбросов между
  измерениями. Это не системный демон: сторонние задачи и прямой запуск
  бинарника в обход скрипта не защищены и не завершаются им.

**11 интеграционных тестов PASS** (`python3 tools/test_gpu_guard.py`, финальный прогон 10,188 с).
Все опасные температуры/отказы подставлены через fake `nvidia-smi`, нагрузка —
CPU-only disposable processes. Проверены 69/70, горячая вторая карта,
TERM-игнорирующие дочерние процессы, сигналы сторожу, его SIGKILL, исчезнувшая/
невалидная/зависшая телеметрия, запрет повышения порога и подключение `run.sh`.
Добавлена проверка `GPU_GUARD_LOG`: журнал preflight/запуска/выхода сохраняется.
Дополнительный live smoke с настоящим датчиком и CPU-sleep: 46 °C, exit 0.
`bash -n`, `py_compile`, `gdlint` нового audit-скрипта и `git diff --check` PASS.

Ошибка прежней процедуры: исторический `measure.py` лишь прерывал **сбор данных**
при >=85 °C, не закрывая приложение. Это не температурная защита. Исходный
измеритель сохранён как доказательство; использовать его как сторож запрещено.
Правило 70 °C добавлено в AGENTS проекта и рабочей области для наших будущих
локальных GPU-экспериментов. Сервисы/драйвер/частоты/питание/вентиляторы не менялись.

## Найденные источники лишней работы

### 1. Глобальные MultiMesh-батчи, без индивидуального отсечения и LOD

`scripts/vegetation.gd:54` собирает **все** особи одного вида по всей долине
в один MultiMesh. Нет пространственных чанков, LOD или отбора по размеру на
экране. Даже всход получает полный видовой меш, только меньший transform.
Когда AABB батча виден, GPU получает его особи целиком, в том числе вне камеры.
Это документированная граница MultiMesh, не особенность конкретного вида.

Число живых растений в сохранённых GUI кадрах выросло с 3905 до 17751.
Это поддерживает связь ускорения с растущей ценой последующего рендера:
возврат на ×1/паузу не удаляет уже выросшую геометрию. Точный состав и число
всех инстансов на момент сбоя не восстановлены; погибшие особи тоже остаются
в append-only видовых массивах.

### 2. Вся растительная геометрия неиндексированная

`scripts/plant_mesh_builder.gd:5` разворачивает исходные индексные меши в
triangle soup, вызывает `add_vertex()` на каждый угол и делает `commit()` без
`index()`. В vertex shader при этом выполняются ветер/sin/pow; есть до четырёх
солнечных shadow-split проходов (`scripts/atmosphere.gd:45`). Уменьшение числа
пикселей не сокращает число этих вершин. Shadow split — дополнительная цена,
но точное число реально нарисованных треугольников по каскадам не измерено.

CPU-only `tools/audit_render_budget.gd`, настоящий headless display, **без**
создания игровой сцены/отображения/продвижения времени/загрузки user save:

| Величина для текущей начальной seeded-популяции | Значение |
| --- | ---: |
| Особи | 3482 |
| Треугольники в растительных батчах на один полный геометрический проход | 4 455 300 |
| Поданные вершины без индексов | 13 365 900 |
| Уникальные вершины при индексировании тех же мешей | 2 413 733 |
| Отношение | 5,537× |
| Неиндексированные виды | 29 из 29 |

Это бюджет инстансов, **не** измеренный счётчик GPU после frustum-culling и не
реконструкция упавшего мира. Для индексной копии по каждому углу сверены позиция,
нормаль и цвет: позиции и цвета совпали точно; максимальная повторная ошибка
упаковки нормали 0,00012835. Треугольники не удалялись. Уменьшение вершин на
81,94% **не означает** такое же снижение ваттности/FPS: остаются растеризация,
shadows и остальные проходы.

Важная смежная зависимость: `vegetation.gd:89` читает foliage-теги, предполагая
неиндексированные углы. Добавлять один `surface.index()` без исправления этого
пути нельзя: сломается точное выделение/фенология листьев в observer.

### 3. Анимированное небо продолжает обновлять radiance на паузе

`shaders/painterly_sky.gdshader:37` использует TIME; `atmosphere.gd:21` задаёт
radiance 256 и REALTIME. Официальная документация указывает: TIME делает
radiance cubemap грязной **каждый кадр**. Кроме фонового неба, получается
повторная procedural-cloud работа для освещения/отражений. Игровой `paused`
останавливает модель, не это TIME. Здесь же есть SSAO, glow и двусторонний
foliage shader с discard. Их индивидуальная цена не измерена.

Документация механизма (Godot upstream; проверена 2026-11-01, не профиль Redot):

- https://docs.godotengine.org/en/stable/tutorials/performance/using_multimesh.html
- https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/sky_shader.html

## Граница первоначального аудита, до продолжения

Найден не один «магический shader», а тяжёлое представление геометрии с
отсутствующим отсечением/упрощением, дублированными вершинами и непрерывными
фоновыми проходами. Это конкретные проверенные источники затрат; распределения
246 Вт между ними пока нет. Новый thermal soak для подтверждения не проводился.

На этапе первоначального аудита были изменены **сторож и запуск**, не рендер.
Намеченный порядок оптимизации: индексирование с сохранением picking-контракта;
пространственные батчи и геометрические LOD без изменения биологии;
разделение видимых облаков и дешёвого/редко обновляемого radiance. Экономию
мощности/сохранение картинки до реализации и проверки не заявлять.

## Реализовано после продолжения: удаление лишних затрат

Павел: «ну так выкидывай лишние затраты по ходу пьесы». Выполнено в этом же
checkout, с сохранением всех предшествующих незакоммиченных изменений.

1. `ForestPlantMeshBuilder.build()` вызывает `surface.index()` **до** commit.
   Число поданных вершин для той же seeded-популяции 3482 особи уменьшилось
   **13 365 900 → 2 413 733 (−81,94%)**. Все 4 455 300 треугольников сохранены.
   `triangle_foliage()` читает метки в порядке индексов, совпадающем с
   `get_faces()`; picking не полагается на прежний colors[::3]. До правки
   сохранён полный CPU-базис массивов 29 мешей `mesh-baseline.bin`. После правки
   сверены **каждый угол каждого вида**, позиция, нормаль, цвет и foliage-тег.
   Проверка с переставленными индексами отклоняет прежний неправильный reader.
2. Долина делится на **4×4** презентационных участка, размер выводится из
   `settings.extent`. Пары вид/участок — отдельные MultiMesh: в начальном мире
   **458 непустых батчей**, но всего **29 общих мешей/материалов**. Стабильные
   ID и per-ID slot→batch сохраняются при добавлении всхода. Geometry LOD и
   лимит особей не менялись. Custom AABB объединяет фактически показанные
   границы с консервативным ростом: невидимые резервные slots не растягивают
   каждый участок до (0,0,0). Ранее накопленные границы не сжимаются, чтобы
   рост/интерполяция не отсекали видимый объект. Wind cull-margin 3 м сохранён.
3. В `painterly_sky.gdshader` проход `AT_CUBEMAP_PASS` получает дешёвый
   атмосферный градиент без обоих `cloud()` noise-вычислений. **Видимое** небо и
   анимация облаков не менялись. Отражение неба теперь сглаженное, без детальных
   облаков. Cubemap всё ещё может обновляться из-за TIME; устранена дорогая
   облачная работа внутри него, не все обновления radiance. Повторные записи
   неизменных sky uniforms отсечены кешем значений.
