## Migration

Checked the official [upgrade path](https://terrain3d.readthedocs.io/en/1.1/docs/installation.html)
and [API changes](https://github.com/TokisanGames/Terrain3D/discussions/756).

- `get_height()` is now a raw vertex lookup; `get_surface_height()` retains
  interpolation and material region blending. Updated initial vegetation
  placement, ground-card height/culling, footprints and related render tools.
  This preserves presentation placement, not a new biological height field.
- `Terrain3DAssets.set_texture_asset()` replaces `set_texture()`.
  `Terrain3DTextureAsset.set_asset_name()` is the renamed setter, while the
  exported property remains `name`, not `asset_name`.
- Rebased our ecological soil shader onto upstream 1.1 `lightweight.gdshader`,
  retaining the upstream MIT notice and our field-driven wetness, humus,
  litter, living cover, sand, trampling, rooting, snow and scientific layers.
  New clipmap target/camera uniforms, region lookup and packed-normal AO code
  come from the new base. The custom smooth surface-noise function is retained.
- Main-forest tessellation is explicitly **0**: the lightweight shader does
  not implement the native displacement-buffer path. Ocean remains disabled.
  The shader's MAX_REGIONS is 1024, matching the material's default limit.
- First import/preview attempts caught a nonexistent `asset_name` property,
  an omitted custom noise function, and an old AO local-name collision. These
  were fixed in application files; final runtime logs have no such errors.

## Feature studies: not shipped defaults

`preview_terrain_features.gd` swaps only presentation resources on a paused
forest. All models stay byte-identical. Native samples use the existing turf
albedo/height and numerically pack its normal/roughness/AO into the 1.1 format:
normalized normal vector scaled by `sqrt(AO)*.5+.5`, then encoded to RGB.
The existing ecological material is not silently replaced in the main forest.

| Feature | Observed result | Decision/boundary |
| --- | --- | --- |
| Packed AO | Mean absolute image RGB difference 0.00273835; unchanged-render control 0 | Supported and useful material mechanism; our turf already had AO, so this is not a new global SSAO effect |
| Native displacement, tessellation 2 | Zero/nonzero displacement image difference 0.00698843 at global scale .12 m; submitted primitives roughly 235k → 327k | Works; keep experimental, especially with grass-height maps. Local soil/sand studies are more appropriate than globally enabling it |
| Contours | Native debug view rendered successfully | Inspection tool, not the main art style |
| Particle grass | 57,600 particles across 9 nodes, rendering and terrain placement work | Source of techniques, not a drop-in replacement: stock look differs, TIME-driven motion and no project snow/water/traffic/rooting/ecology masks |
| Ocean clipmap | Separate static-level native ocean rendered in the valley, model bytes unchanged | Demo only, not a substitute for our finite-volume river; sea-level/waves do not own water mass |

AO/displacement comparisons exclude the changing top caption (80 pixels).
The same-parameter native AO repeat has exactly zero image difference; AO
exceeds this control. Displacement is compared at the same tessellation with
global displacement 0 versus .12, not inferred from a shader parameter alone.
The supplied displacement is visual: `get_surface_height()` remains the base
surface; collision/hydrological height is unchanged.

An initial test's expectation of at least 1.5× total submitted primitives was
rejected by the actual clipmap result (~1.39×): additional inner LODs do not
subdivide the entire submitted mesh uniformly. The replacement visual assay is
a new zero/nonzero check of displacement, not confirmation of that old count
threshold or a performance win.

Brief timing samples fluctuate even on return controls; densities, shapes,
coverage and wind are not matched between grass systems. No FPS improvement,
fill-rate diagnosis, CPU/GPU speedup or particle superiority is claimed.
Current grass is already GPU-rendered with field masks/wind; a GPU placement
prototype could target CPU patch construction, not automatically reduce pixel
overdraw. The previous grass report similarly withheld unstable GPU timing claims.
